# instead of failing to import) - this lets the package's cross-platform
# pure-logic modules and their tests can run on non-Windows hosts without any of
# these installed. They are required to actually run the app on Windows.

# WinRT projections for BLE GATT (Bluetooth Low Energy Generic Attribute
# Profile) access to the RC003's ATVV voice service.
#
# Foundation and Foundation.Collections (XRBM-024): the official 3.2.1
# wheels for Devices.Bluetooth/Bluetooth.GenericAttributeProfile/
# Devices.Enumeration/Storage.Streams above declare winrt-runtime as their
# only BASE dependency - winrt-Windows.Foundation[all] and
# winrt-Windows.Foundation.Collections[all] are declared only as an "all"
# EXTRA, which this project deliberately does not pull (see below). But the
# call surface those base packages actually return at runtime does need
# both: DeviceInformation.find_all_async_aqs_filter() returns a
# Windows.Foundation.IAsyncOperation, and iterating the resulting
# DeviceInformationCollection uses a Windows.Foundation.Collections
# IIterator (see ble_transport_winrt.py's discover_candidates()). Without
# these two exact pins, that call raises
# "ModuleNotFoundError: No module named 'winrt.windows.foundation'" the
# first time discover_candidates() actually awaits it - passing every
# source-level test but crashing at first real BLE use (XRBM-024 red
# evidence, real Windows Actions run 29643131337).
#
# Pinned as plain base packages, NOT the "[all]" extra: "[all]" would pull
# in every other namespace those packages' own "all" extras reference
# (ApplicationModel.Background, Security.Credentials, UI, UI.Popups, Storage,
# System, Networking, Radios, Rfcomm, ...) - none of which
# ble_transport_winrt.py uses. Only the two exact projections this module's
# real call surface needs are added.
winrt-runtime==3.2.1
winrt-Windows.Devices.Bluetooth==3.2.1
winrt-Windows.Devices.Bluetooth.GenericAttributeProfile==3.2.1
winrt-Windows.Devices.Enumeration==3.2.1
winrt-Windows.Storage.Streams==3.2.1
winrt-Windows.Foundation==3.2.1
winrt-Windows.Foundation.Collections==3.2.1

# Alternate button input source: the ESP32-C6 BLE bridge
# (esp32_serial_input.py).  The firmware in `esp32-c6-bridge/` acts as a BLE
# central to the RC003 and forwards raw HID usages over USB CDC, which is the
# only way to recover the three usages Windows' own HID stack drops (0x00F1
# back, 0x0080 volume up, 0x0081 volume down) - the HID service is exclusively
# held by mshidumdf, so no user-mode GATT client can subscribe to it.
#
# NOT required for the default `windows_hid` input source: esp32_serial_input.py
# guards this import and raises Esp32SerialUnavailableError, so a machine
# without pyserial can still run every other code path.  Only install it if you
# actually intend to select the ESP32 bridge as the input source.
#
# BSD-3-Clause; see THIRD_PARTY_NOTICES.md.
pyserial==3.5
